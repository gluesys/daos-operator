# 실장비 검증 기록 — daos_ci (2026-09-15)

대상: FlexA 테스트베드 daos_ci — 서버 34.21/34.22(DAOS 2.8.0, 시스템 이름 `daos_flexa`, `ofi+verbs;ofi_rxm`, 풀 nvme_pool/hdd_pool),
클라이언트 34.20(Rocky 8.7, podman 4.9, 호스트 `daos_agent`, ib0 172.28.136.254). **서버 재시작·포맷 없이** 컨테이너 이미지와
operator/CSI 가 실제로 내리는 명령을 그대로 실행했다.

## 1. operator 의 dmg/daos Job 명령 (admin·client 이미지, podman)
| 명령(operator 형태 그대로) | 결과 |
|---|---|
| `dmg -j system query -v` | rank 0,1 joined |
| `bash -c "printf ... > /tmp/daos-acl && exec dmg -o ... -j pool create -z 3221225472B -P rd_fac:0 -r 0 -a /tmp/daos-acl optest"` | uuid b7dc850d…, tgt_ranks [0] |
| `dmg -j pool query --show-enabled optest` | state Ready, `enabled_ranks` **배열** 형식(파서 양쪽 지원 확인) |
| `dmg -j pool get-acl` / `overwrite-acl -a` | ACL 교체 확인 |
| `dmg -j pool extend --ranks=1 optest` | `{"response":null,"error":null}` → enabled_ranks [0,1], rebuild busy |
| `daos -j cont create optest optest-c --type POSIX --file-oclass RP_2GX --dir-oclass RP_2G1 ... --properties rd_fac:1,cksum:crc32 --acl-file` | **실패** `grp size (2) is larger than domain nr (1)` — 단일 노드(장애 도메인 1)에서 RP_2 불가 |
| 같은 명령, `--file-oclass SX --dir-oclass S1 --properties rd_fac:0,cksum:crc32` | 성공; 응답 JSON = `cont query` 와 동일 구조(파서 확인) |
| `daos -j cont query/get-prop/overwrite-acl/destroy`, `dmg -j pool destroy --recursive` | 모두 성공, 정리 완료 |

발견 → 반영:
- 시스템 이름이 `daos_server` 가 아닌 경우(`daos_flexa`)가 실존 → `spec.systemName` 추가, 컨테이너 Job 의 `daos` 에 `-G <name>`.
- RP_2GX/RP_2G1 기본값은 서버 노드 2대 이상 전제. CRD 주석·CSI StorageClass 예시에 명시.
- podman(SELinux) 에서 파일 마운트는 `--security-opt label=disable` 필요(K8s ConfigMap 마운트에는 해당 없음).

## 남은 것
- K8s 클러스터가 있는 실장비(GPU 노드 또는 전용 스토리지 노드)에서 helm install → PVC → 파드 마운트까지: Phase 2 종료 기준의 마지막 단계.
- 서버 컨테이너(StatefulSet) 기동은 FlexA 네이티브 daos_server 와 NVMe 를 공유할 수 없어 이 테스트베드에서는 하지 않았다(소유자 승인 + 전용 장비 필요).
